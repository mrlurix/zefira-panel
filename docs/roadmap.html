Roadmap

What is finished, what is being worked on, and what is deliberately not planned. Every item here is a statement about the code, not an intention — where something is not done, this page says so and says why.

Shipped

Things that work today. If a line here is wrong, it is a bug in the code or a bug in this page, and either way one of them should be changed.

  • Installation in one command: pinned to a release tag, verified against a commit SHA, hash-locked Python dependencies, and non-interactive when there is no terminal.
  • Secrets at rest are encrypted: customer credentials (WireGuard private key, OpenVPN client keypair, L2TP PSK), the AI key, the Telegram bot token and the REALITY private key are stored under the panel key. Reading the database file or an unencrypted backup no longer yields working credentials.
  • Restore cannot wipe you by accident: an empty customer list is refused, the pre-restore safety copy reports its own failure, and admin credentials and API tokens are never imported from a file.
  • Every settings card is tested end to end: read, change, read back, restore — with the cards that reach outside the panel probed in a way that issues nothing.

Known limits, stated plainly

These are real and not planned away. They are listed here so nobody discovers them in production.

  • One worker: rate limiters, the restore and update locks, and the node-monitor loop live in process memory. Running more than one worker multiplies the rate-limit budgets and can interleave restores. Horizontal scaling needs those moved to shared storage first — that is a real project, not a config flag.
  • SQLite writes serialise: fine for the panel sizes this is built for. PostgreSQL or MySQL are supported through the same code path if you need concurrent writers.
  • No hardware key storage: the panel derives its key from a file on the host. Requiring an HSM or a cloud KMS would make the documented one-command install impossible on the single VPS this is built for, so it is not on the roadmap. If you run it somewhere with a KMS, derive the key there and keep the file as the fallback.
  • Uninstall deletes the database: take a backup first. This is being changed so the confirmation cannot be skipped.

Being worked on

  • A confirmation for --uninstall that cannot be passed non-interactively, plus a backup taken first.
  • The installer refusing a source directory that is world-writable or not owned by root, so a shared download directory cannot feed pip as root.
  • Reporting a certificate failure as a certificate failure: the certbot exit status is currently masked by a pipe.
  • The installer refusing a source tree it does not own: an unprivileged user who shares the directory the docs tell them to download into can have pip run their requirements as root.

Contributing

The test suite is the contract. A change that cannot be shown green by run_all_tests.py is not finished, and a guard that cannot be made to fail proves nothing — so new guards are expected to demonstrate their own failure by breaking the fix on purpose.
