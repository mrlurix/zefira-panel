BackPack tunnel walkthrough (Iran ⇄ Kharej)

  1. Install BackPack on BOTH servers (Iran entry + Kharej exit) with its install script.
  2. Zefira → Tunnels → create node: transport, Iran IP, Kharej IP, tunnel port, forwarded ports (e.g. 443:8000), UDP flag. Copy the one-time token — it must match on both servers.
  3. Iran server: backpack → Setup Iran → same transport, port, name, token, exposed ports, Turbo preset.
  4. Kharej server: backpack → Setup Kharej → same values + Iran address.
  5. Verify: Status on both servers, Health Check on errors, then Zefira Check now probes iran-ip:tunnel-port. Keep the token secret — whoever holds it can join the tunnel.

Transport picks: dirty routes → TCP+Stealth or WSS/WSS-Mux. UDP apps (WireGuard, DNS, games) → enable Forward UDP with KCP/QUIC transports.

No inbound to Iran? Use BackPack Direct mode instead of a reverse tunnel: Setup Iran → Direct → pick a carrier (udp, quic, pck, sni, xdi, spoof). Iran dials out so no inbound port is needed, and forwarded ports work the same. The tunnel port can be pinned to one address (IP:port) in the wizard.

Anti-filter cookbook

  1. REALITY first: Anti-Censorship → Generate keypair (private stays encrypted, reveal is audit-logged) → paste the private key into the Xray server config. Links rotate SNI automatically (xtls-rprx-vision).
  2. Stack layers on dirty networks: REALITY or Hysteria2 + obfuscated host (a weird CDN URL hiding the real IP) + per-user subdomains (needs wildcard DNS *.host — every user gets a random prefix) + CDN SNI spoofing + block-direct-IP (panel reachable only via domain).
  3. Monitor: Nodes section tracks remote servers (status/latency/uptime every 5 min). Pin inbounds to a node — offline/disabled nodes drop out of every subscription link automatically until recovery.
  4. Diagnose 404s: user expired/disabled/out-of-volume? Then Settings domain/ports, server firewall ports, REALITY keys / WireGuard public key. Sub loads but clients can't connect = server-side ports or keys, almost always.

Transport hardening: server and client

The panel's Transport Hardening card changes what it writes into links and Clash profiles. Two of those settings need a matching server change before they can work; the TLS fingerprint and per-user REALITY SNI need none.

  • Hysteria2 obfs (Salamander): set the same password on the server before enabling it in the panel. A minimal server fragment:
    obfs: {type: salamander, salamander: {password: YOUR_PASSWORD}}
    Every Hysteria2 link then carries obfs=salamander&obfs-password=…, and Clash carries the same two keys. A mismatched password fails the handshake, not the TCP connection — the client just times out.
  • Hysteria2 port hopping: listen on the range (Hysteria's Linux server can do this directly) or DNAT the range to the normal port, then open the same UDP range in the firewall.
    listen: :20000-50000
    Manual DNAT fallback: iptables -t nat -A PREROUTING -p udp --dport 20000:50000 -j REDIRECT --to-ports 8443
    Links use mport=…&hop-interval=… and Clash uses ports: plus hop-interval:. Port hopping does not help when the ISP blocks UDP entirely.
  • TLS fragmentation is a client setting: the panel cannot put it in a share link. Turn it on in the client when the TLS handshake itself is being blocked: sing-box tls.fragment, Hiddify's Fragment switch, or v2rayN/v2rayNG's Fragment option. It is not needed on a clean route and adds overhead.
Do not enable obfs or port hopping until the server matches. Both are off by default for exactly that reason: turning them on without the server-side change breaks every Hysteria2 link while the panel still reports a healthy save.

Server alignment: match an existing Xray / Hysteria2 server

The Server Alignment card is for servers you did not build from this panel. It changes only what the panel writes into links and Clash profiles; every field is optional and an empty value keeps the historical behaviour.

  • REALITY shortIds: paste the server's real shortIds array (comma separated) or use Generate and copy the values into Xray first. With a list, the panel emits one link per ID; without it, links keep using the old SHA1-derived IDs, which the server must already contain.
  • WebSocket path and Host: set them when the server's wsSettings.path or Host header is not /zefira and the connect address. The same values go into VLESS, VMess and Trojan links and Clash profiles.
  • Hysteria2 hop URI format: choose official for the official Hysteria2 client, which reads the port range from the URI authority. The default mport extension is what v2rayN, Xray and Shadowrocket read; the official client ignores it.
  • Clash automatic failover: adds a fallback group named Zefira-Auto with a health-check URL and interval. The manual Zefira selector stays, so customers can still pin a proxy. Off by default.
  • Run Diagnostics: checks the saved values for the mismatches the panel can see: missing or invalid REALITY keys, legacy shortIds, a CDN SNI without a Host override, an anchor port outside the hop range, and Clash failover state. It never changes a setting.
The panel cannot read the remote Xray or Hysteria2 config. Diagnostics are hints, not a server audit; the final check is a real client connection.

Point an AI client at the panel

  1. Switch the MCP server on in the panel, and create a token with the full scope under Developer API.
  2. Point the client at POST /api/mcp with Authorization: Bearer …. No cookie and no CSRF header: a cookie is refused outright.
  3. The client lists the 25 tools it can call. The destructive ones refuse to run until the call carries the exact confirmation string the refusal names.
