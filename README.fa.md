> 📚 **مستندات: [mrlurix.github.io/zefira-panel](https://mrlurix.github.io/zefira-panel/)** — راهنمای نصب، راهنمای کاربر، مرجع API، پرسش‌های متداول.

پنل ساده برای مدیریت و فروش حساب VPN. به‌عنوان ابزاری خصوصی برای سرورهای خودم شروع شد و برای استفادهٔ عمومی تمیز شد.

با VLESS، VLESS-REALITY، VMess، Trojan، Shadowsocks، Hysteria2، WireGuard، OpenVPN، L2TP/IPsec، Cisco AnyConnect و SOCKS5 کار می‌کند. هر کاربر می‌تواند هم‌زمان چند پروتکل داشته باشد و **یک** لینک اشتراک می‌گیرد.

ساخته‌شده با FastAPI + SQLite. نیازی به Docker نیست، فقط پایتون.

### نصب روی سرور

یک‌خطی:

```bash
curl -fsSL https://raw.githubusercontent.com/mrlurix/zefira-panel/main/install.sh | sudo bash
```

ترجیح می‌دهید اول بخوانید؟ دانلود کنید، نگاه کنید، سپس **همان** نسخه را اجرا کنید:

```bash
d="$(mktemp -d)"                       # پوشه‌ای خصوصی که فقط خودتان می‌خوانید
curl -fsSL -o "$d/install.sh" \
  https://raw.githubusercontent.com/mrlurix/zefira-panel/v1.15.16/install.sh
less "$d/install.sh"
sudo bash "$d/install.sh"
rm -rf "$d"
```

> هر دو کار می‌کنند. حالت یک‌خطی هرچه upstream در آن لحظه سرو می‌دهد را مستقیم به یک shell ریشه می‌فرستد، پس اگر برایتان مهم است که **چه** کدی به‌عنوان root اجرا شود، حالت دوم را به کار ببرید: در پوشه‌ای فرود می‌آید که `mktemp` همین الان برای شما ساخته (یک مسیر ثابت مثل `/tmp/zefira-inst` را کاربر محلی دیگری می‌تواند از قبل ساخته باشد و `mkdir -p` بی‌سروصدا روی پوشه‌ای که مالکش نیست موفق می‌شود)، و تگ `v1.15.16` خودِ نصب‌کننده را pin می‌کند.
>
> سپس نصب‌کننده کد پنل را از تگ انتشاری که همراهش می‌آید clone می‌کند. اگر می‌خواهید سخت‌گیرانه‌تر pin کنید و کامیت دقیق را نام ببرید:
>
> ```bash
> ZEFIRA_EXPECTED_SHA=<کامیت ۴۰ کاراکتری> sudo bash install.sh
> ```
>
> مگر آن‌که clone دقیقاً همان کامیت باشد رد می‌شود. `ZEFIRA_INSTALL_REF=main` رفتار قدیمی‌ترِ «دنبال شاخه رفتن» را برمی‌گرداند. نصب‌کننده همچنین استفاده از خودِ `/opt/zefira` به‌عنوان منبع را رد می‌کند: آن درخت برای حساب سرویس قابل‌نوشتن است، پس اعتماد به آن یک foothold سرویس را به root تبدیل می‌کند.

اسکریپت وابستگی‌های پایتون را نصب می‌کند، یک سرویس systemd می‌سازد و اطلاعات ورود اولیه را در `instance/first-run-credentials.txt` (mode 600) ذخیره می‌کند — با `sudo cat` بخوانید و بعد از اولین ورود حذفش کنید. روی Ubuntu / Debian / Alma / Rocky کار می‌کند (نیازمند پایتون ۳.۱۰ به بالا).

اگر گزینهٔ nginx فعال باشد، پنل فقط روی `127.0.0.1` گوش می‌دهد و فایروال فقط ۸۰/۴۴۳ را باز می‌کند؛ بدون آن، پنل روی پورت انتخابی HTTP ساده پاسخ می‌دهد، پس پیش از استفاده با حساب واقعی TLS را جلوی آن بگذارید.

برای حذف بعدی: `sudo bash install.sh --uninstall`

### نصب دستی

```bash
git clone https://github.com/mrlurix/zefira-panel.git
cd zefira-panel
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn main:app --host 127.0.0.1 --port 8000 --no-server-header --no-proxy-headers
```

روی `127.0.0.1` گوش بدهید و یک reverse proxy با TLS جلوی آن بگذارید. `--host 0.0.0.0` ورود ادمین را به‌صورت متن ساده منتشر می‌کند (بدون Secure cookie، بدون HSTS).

اجرای اول نام کاربری/گذرواژهٔ ادمین را در `instance/first-run-credentials.txt` (mode 600) می‌نویسد و فقط مسیر را چاپ می‌کند. اگر پیش از شروع `ZEFIRA_ADMIN_PASSWORD` را تنظیم کرده باشید، همان استفاده می‌شود.

> **دقیقاً یک worker اجرا کنید.** محدودکننده‌های نرخ، قفل‌های restore/update، حلقهٔ پایش نود و کش تنظیمات در حافظهٔ همان process زندگی می‌کنند — `--workers N` بودجهٔ محدودسازی نرخ را ضرب می‌کند و می‌تواند restoreها را درهم بیندازد. با ماشین بیشتر مقیاس بگیرید، نه با worker بیشتر.

ورود پیش‌فرض: `http://YOUR_SERVER_IP:8000`

### چه چیزی به دست می‌آورید

- کاربر با محدودیت ترافیک، تاریخ انقضا و یادداشت. اگر می‌خواهید تایمر فقط بعد از اولین اتصال شروع شود، start-on-first-use پشتیبانی می‌شود. دکمهٔ مداد هر ردیف یادداشت، حجم، انقضا و محدودیت دستگاه را ویرایش می‌کند.
- چند پروتکل برای هر کاربر، همه در یک اشتراک. از subscription های base64 معمولی و Clash YAML (`?format=clash`) پشتیبانی می‌کند. توضیح لینک نام کاربری ساده را نشان می‌دهد.
- فید اشتراک **فقط share link حمل می‌کند و هیچ چیز دیگر**. `WireGuard`، `OpenVPN`، `L2TP/IPsec` و `Cisco AnyConnect` پروتکل فایلی هستند — یک `.conf`/`.ovpn` URI نیست، پس هیچ importer لینکی نمی‌تواند آن را بخواند — و به‌صورت فایل تحویل می‌شوند: کارت داشبورد، دکمهٔ **Download config** هر کاربر، یا ZIP. بنابراین پلنی که *فقط* از پروتکل‌های فایلی ساخته شده چیزی برای فهرست‌کردن ندارد، و فید به‌جای صفحه‌ای از متن غیرقابل‌پارس، `422` برمی‌گرداند با همین دلیل. پیش از v1.15.8 این فایل‌ها زیر یک هدر `### OpenVPN ###` درون فید-inline می‌شدند؛ کلاینت فقط آن یک خط `#` را رد می‌کرد و نود خط بعدی را به‌عنوان نود تحویل می‌گرفت.
- داشبورد مرورگر: باز کردن لینک اشتراک در مرورگر مصرف، لینک‌ها، QR و اپ‌ها را نشان می‌دهد؛ کلاینت‌های VPN همیشه بایت خام می‌گیرند.
- Inbounds: برای هر پروتکل پورت/میزبان اضافه تعریف کنید و هر کاربر برای همهٔ آن‌ها لینک می‌گیرد. inbounds را به نودهای سرور pin کنید — نودهای آفلاین خودکار از لینک‌ها کنار گذاشته می‌شوند.
- نودهای سرور: ثبت سرورهای راه دور با بررسی سلامت هر ۵ دقیقه، latency و uptime؛ بررسی on-demand، فعال/غیرفعال‌سازی، حذف ایمن.
- ضدسانسور: کلیدهای REALITY را داخل پنل تولید کنید، لینک‌ها از `xtls-rprx-vision` استفاده می‌کنند و SNI خودکار می‌چرخد.
- نودهای تونل BackPack: برای سرورهای ایران/خارج تونل بسازید، راهنمای راه‌اندازی را با توکن پرشده دانلود کنید، و بررسی کنید سمت ایران در دسترس است یا نه.
- کد QR برای هر اشتراک، دانلود ZIP برای کانفیگ‌ها.
- حباب دستیار AI: کمک‌کنندهٔ داخل پنل (Groq-محور، OpenAI/Anthropic/Gemini/Ollama) برای تازه‌واردان.
- به‌روزرسانی یک‌کلیکی از GitHub با پیش‌نمایش changelog، درست داخل پنل.
- توکن‌های API (`zfp_…` bearer) برای ربات‌های تلگرام و داشبوردها — بدون نیاز به هدر CSRF. Scopeها: `full` یا `bot` با کمترین امتیاز (فقط فهرست/ساخت کاربر).
- شخصی‌سازی کامل: رنگ تم، نام برند، پیام داشبورد.
- دروازهٔ گذرواژهٔ قوی روی عملیات حساس، لاگ ممیزی کامل، آمار سیستم، اعلان تلگرام در صورت تمایل.
- پشتیبان‌گیری/بازیابی JSON (هر دو با تأیید گذرواژه)، پشتیبان رمزگذاری‌شدهٔ اختیاری. همچنین همهٔ تنظیمات را import/export می‌کند.
- به‌عنوان کاربر سیستمی بدون امتیاز `zefira` اجرا می‌شود (هرگز root)؛ سهمیهٔ حجم روی اشتراک‌ها اعمال می‌شود.

راهنماهای کامل در سایت مستندات (لینک بالا).

### تنظیماتی که شاید بخواهید عوض کنید

بیشتر چیزها داخل خود پنل است: **Settings -> Server / Hosts Settings** (دامنه، پورت‌ها، DNS، تنظیمات REALITY) و **Settings -> Remote Access** (URL عمومی، پروکسی‌های مورد اعتماد).

اگر فایل env را ترجیح می‌دهید، `.env.example` را به `.env` کپی کنید. متغیرهای env فقط به‌عنوان پیش‌فرض در اولین اجرا استفاده می‌شوند.

### امنیت

سعی کردم سفت نگه دارم: scrypt برای گذرواژه‌ها، JWT در کوکی‌های HttpOnly، محدودسازی نرخ روی ورود (به تفکیک IP مبدأ، پیش از هر هش)، بررسی CSRF، سخت‌گیرانه CSP، کوئری‌های پارامتری، بدون innerHTML برای دادهٔ کاربر، و لاگ ممیزی.

**آنچه رمزنگاری می‌شود:** اطلاعات تلگرام/AI، کلیدهای میزبان REALITY و WireGuard، توکن‌های تونل و پشتیبان‌های رمزگذاری‌شده (AES/Fernet با `instance/secret.key`). **آنچه رمزنگاری نمی‌شود:** اعتبارهای VPN هر مشتری در پایگاه داده (`secret_data`) — JSON ساده در `instance/zefira.db` و در پشتیبان رمزنگاری‌نشده، به‌عمد تا پنل بتواند لینک‌ها را بدون یک دور decrypt بازسازی کند. پایگاه داده و پشتیبان‌های رمزنگاری‌نشده را **اعتبار مشتری** بدانید: `instance/` را روی `700` نگه دارید، از پشتیبان رمزگذاری‌شده یا رمزنگاری کل دیسک استفاده کنید، و [SECURITY.md](SECURITY.md) را ببینید.

### اجرای تست‌ها

[مجموعه‌های تست](#اجرای-تستها) از بیرون به پنل در حال اجرا ضربه می‌زنند. پنل را بالا بیاورید، سپس هرکدام را اجرا کنید (بین مجموعه‌ها پنل را ری‌استارت کنید). برای اجرای همه با هم: `python run_all_tests.py admin YOURPASS`. مجموعه‌ها مستقل از ترتیب‌اند و در پایان همه به تنظیمات پیش‌فرض کارخانه برمی‌گردند.

**زنده (۹ مجموعه)** — به پنل در حال اجرا نیاز دارند:

```bash
python security_test.py      http://127.0.0.1:8000 admin YOURPASS  # سوءاستفاده/دفاع
python functional_test.py    http://127.0.0.1:8000 admin YOURPASS  # جریان‌های سرتاسری
python feature_test.py       http://127.0.0.1:8000 admin YOURPASS  # پوشش قابلیت‌ها
python attack_test.py        http://127.0.0.1:8000 admin YOURPASS  # پروب‌های حملهٔ زنده
python attack_quota_test.py  http://127.0.0.1:8000 admin YOURPASS  # مرزهای سهمیه/اسکیما
python attack_paths_test.py  http://127.0.0.1:8000 admin YOURPASS  # مسیرهای اپراتور
python frontend_bugs_test.py http://127.0.0.1:8000 admin YOURPASS  # رگرسیون فرانت‌اند
python panel_sections_test.py http://127.0.0.1:8000 admin YOURPASS  # بخش‌های پنل
python security_audit_test.py http://127.0.0.1:8000 admin YOURPASS  # ممیزی امنیتی
```

`feature_test.py` همهٔ ۷۷ مسیر API را در ۱۱ بخش پنل پیمایش می‌کند و ادعا می‌کند هر قابلیت واقعاً **قابل استفاده** است (لینک واقعی در اشتراک، QR قابل رمزگشایی، آرشیو کانفیگ کارکننده، ماتریس scope ربات، round-trip پشتیبان/بازیابی…) نه صرفاً در دسترس. `attack_test.py` خودش ترافیک خصمانه را شلیک می‌کند: جعل هدر، XSS ذخیره‌شده، path traversal، بدنه‌های بیش‌ازحد/تودرتو، ترفندهای یونیکد/encoding، timing oracle، سیل ورود، تلاش برای بیرون‌انداختن limiter، و کل ماتریس احراز هویت.

**بدون سرور (۹ مجموعهٔ پایتون)** — کد واقعی را اجرا می‌کنند نه اینکه بخوانند، چون هر نقص زیر از بازبینی در سطح منبع رد شده بود:

```bash
python installer_test.py         # تضمین‌های نصب‌کننده، به‌صورت گارد ایستا
python dashboard_link_test.py    # لینک داشبورد مشتری، در نصط با دامنهٔ حدسی
python proxy_trust_test.py      # اعتماد به پروکسی و توافق client IP
python link_encoding_test.py    # کدگذاری توضیح share-link
python update_guard_test.py     # گارد نفوذ runtime در به‌روزرسان
python migration_guard_test.py  # مراحل مهاجرت اسکیما، هرکدام تراکنش مستقل
python env_symlink_guard_test.py # نوشتن .env از طریق symlink توسط نصب‌کننده
python bump_assets_guard_test.py# ورودی‌های bump کردن asset مستندات
python i18n_test.py             # قالب‌ها و JS پنل در برابر همهٔ localeها
python docs_coverage_test.py    # هر endpoint، بخش و تنظیم مستند شده
```

**بدون سرور (۲ اسکریپت Node)** — برای چهار زبان سایت مستندات:

```bash
node i18n_dict_check.js         # دیکشنری‌های مستندات، بارگذاری و بازرسی‌شده
node i18n_render_check.js       # رندرر مستندات، با ورودی‌های خصمانه
```

`i18n_dict_check.js` وجود دارد چون مستندات چهار زبان است که باید هماهنگ بمانند و هیچ‌چیز این را بررسی نمی‌کرد. فایل `docs/assets/i18n.js` را بارگذاری می‌کند، همان شیئی را که مرورگر می‌گیرد می‌خواند، و روی کلیدی که در هر زبانی گم یا خالی است، مقداری که دو ورودی به‌هم‌چسبیده دارد، mojibake، صفت `data-i18n` با املای اشتباه، و صفحه‌ای که به کلیدی ارجاع می‌دهد که در هیچ زبانی نیست شکست می‌خورد. برای مقادیری که **یکسان با انگلیسی** هستند گزارش می‌دهد ولی شکست نمی‌خورد، چون گاهی درست است: `GitHub Security Advisories` نام رسمی قابلیت گیت‌هاب است.

پس از ویرایش هر چیزی زیر `docs/`، اجرا کنید `python docs/build_index.py`. این فهرست جست‌وجو را بازمی‌سازد، به هر سرتیتر لنگر پایدار می‌دهد، و **خودش** شمارندهٔ cache-bust دارایی‌ها را از طریق `docs/bump_assets.py` بالا می‌برد. آن بخش تزئینی نیست: شمارنده چهارده جا زندگی می‌کند، و بالا بردنش فقط در دوازده صفحه باعث می‌شود `docs.js` و `support-ai.js` نسخهٔ **قبلی** `search-index.json` و `site-knowledge.json` را بگیرند — HTML تازه، نتایج جست‌وجوی کهنه، و ربات پشتیبانی که از پایگاه دانش هفتهٔ قبل جواب می‌دهد.

شمارش هر مجموعه عمداً اینجا نوشته نمی‌شود: با هر چک جدید تغییر می‌کند، و عددی که کهنه شده باشد از نداشتن عدد بدتر است چون چیزی به‌نظر می‌رسد که بتوان با آن مقایسه کرد. از خودِ اجرا بخوانید — هر مجموعه `N/N checks passed` چاپ می‌کند.

### وابستگی‌ها

`requirements.txt` پین‌های **مستقیم** نگهداری‌شده توسط انسان را دارد (آنچه را عمداً ارتقا می‌دهید). `requirements.lock` مجموعهٔ کاملاً حل‌شده و **قفل‌شده با hash** است که `install.sh` و به‌روزرسان داخل پنل واقعاً نصب می‌کنند:

```bash
pip install --require-hashes --no-deps -r requirements.lock
```

پین‌های دقیق top-level هرگز گراف وابستگی‌های غیرمستقیم را pin نکردند — `uvicorn[standard]` به‌تنهایی یک dozen بازهٔ نسخه را می‌کشد — پس دو نصب از یک `requirements.txt` یکسان می‌توانستند کد متفاوتی اجرا کنند. بعد از ویرایش `requirements.txt` قفل را دوباره بسازید، سپس تأییدش کنید:

```bash
python tools_lock.py
python verify_lock_hashes.py
```

> **همیشه verifier را اجرا کنید.** قفل روی یک ماشین ساخته و روی ماشین دیگری نصب می‌شود، و hashای که فقط پلتفرم ماشین سازنده را پوشش دهد نصب را روی سرور قطع می‌کند — یا بدتر، قفلی به‌جا می‌گذارد که هیچ‌چیز را تأیید نمی‌کند. نسخهٔ قبلی `tools_lock.py` فقط artifactهایی را ثبت می‌کرد که می‌توانست محلی دانلود کند، که ۱۱ بسته از ۳۱ بسته را روی لینوکس غیرقابل‌نصب می‌گذاشت. `verify_lock_hashes.py` هر hash ثبت‌شده را در برابر PyPI بررسی می‌کند.
